# Aerospace 案例模式

本文件记录 Simio Aerospace 项目对通用仿真规划方法的启发。它是示例与回归素材，不是默认生产模式。

## 可复用的规划模式

| 案例特征 | 可迁移的启发 | 不能当作通用规则的内容 |
|---|---|---|
| 五个串联工位及分组优先任务 | 规范任务标识、优先关系、时间和资源需求；验证并行组与汇合 | 所有流程都是串联，或都用序号定义前驱关系 |
| 四日脉动，未完工作随飞机后移 | 当业务规则允许位置与工作责任分离时，分开记录并显式统计工单和清空工作 | 每条节拍线都会有带走工作，或原工位人员都会跟随处理 |
| 完工驱动方案比较工位容量与缓冲 | 比较放行/流转策略，区分加工能力与排队空间 | 增加能力或减少缓冲总是更好 |
| 本地与灵活用工策略 | 检查人员资格、同时需求、资源竞争，以及理论上界与可行方案的差距 | 全员共享资源池在现场可行 |
| 新机型、双线、班次与加班 | 明确目标、负荷平衡、排班和成本假设 | 机型比例、班次时间、工资倍率可以直接迁移 |
| 有限批次，产线结束后仍有补工 | 区分产线离开、最终完工、完工间隔 CT、流程时间和批次完工 | 有限批次的排空结果可以证明长期稳定性 |

## 可迁移到通用流程的教训

- 案例同时提出“100 架、3.5 天节拍”和“与原计划在相同时间完工”。这是两个不同验收标准，必须分别计算。
- 基准结果曾从约 346 天变为约 316 天，原因是资源预约属性变化。单写“版本不同”无法解释结果；受控的单因素原生运行才定位了差异。要记录会改变行为的关键原生属性，并先调查不明差异再解释业务含义。
- 一个名为“确定性时长”的开关不一定让所有随机机制都确定。应检查每个随机分支和随机流。
- `OwnerCell` 与 `CurLoc` 是不同业务状态。仅在责任工位可能不同于实体位置时，才适用这种解耦模式。
- 人力利用率、付薪工时和编制人数使用了不同分母。要区分每班岗位、独立员工和同时可用人力。
- 逾期人工时代理值不等于实际超期加工人时。代理指标必须标注为近似值，不能当成审计成本或真实工作内容。
- Dashboard 能显示数据，不代表可编辑定义或数据绑定完全有效。数值、绑定、渲染和可维护性要分别检查。
- 已保存候选包、活动模型和发布包是不同模型身份。必须核验用户实际收到的准确文件。

## 案例材料的使用

参考项目包含原始 `Simio Aerospace Data.xlsx`、整理后的 `Tbl_Tasks.xlsx`、多版 `.spfx` 模型、实验原始/汇总数据、验证记录、复盘、最终报告和 Simio 建模原则。把此案例用作回归测试时应重新核查来源转换，不能只依赖叙述性总结。用户后续提供的简单案例应作为前向验证，不应被强行套入 Aerospace 的字段或结构。
