# 通用仿真模型核查规范

用于独立核查仿真项目的 Issue、规划/验证文档、数据文件、模型包、运行结果和“已修复/已完成”声明。适用于 Simio 等离散事件仿真工具；平台特有的读取方法按可用接口另行确定。本规范用于审计证据，不自动授权修改或运行活动模型。

## 核查原则

- 核查结论以可追溯的一手证据为基础。设计说明和摘要可帮助定位，不能替代模型、输入、原始输出和运行记录。
- 从底层数据独立复算能复算的结论；保留单位、公式、样本范围和误差。不可复算或缺证据的内容标为“无法验证”。
- 结论等级与证据强度匹配。静态诊断通过不等于实现正确；实现验证通过不等于真实运营确认；作者报告值不等于本项目仿真输出。
- 核查优先只读。需要运行或临时改动时，先明确授权和影响范围，保存可恢复快照，记录前后差异；结束后恢复并核实现场。
- 发现事实与提出改法分开。核查者不把推测写成事实，不替责任人静默补足证据或关闭待决项。

## 1. 明确核查对象与声明

先定义本次核查的对象、版本、问题和证据边界：

- 项目、模型名称、文件路径、文件格式、版本/哈希、软件版本和活动窗口身份；无法确认时明确记录。
- 核查对象是设计规格、数据质量、模型实现、运行统计、与运营吻合度，还是一条具体的修复/完成声明。
- 目标场景、运行时期、重复编号/数量、输入快照、控制参数、随机流及是否处于运行/暂停状态。
- 当前可以直接检查的内容、无法访问的制品和核查限制。

不要因文件名或 UI 标题相似就认定模型身份。使用可用的路径、哈希、版本属性、修改时间和模型内部标识互相确认。

## 2. 收集一手证据

按核查问题收集并保留原始材料：

- Issue 原文、需求/假设登记、测试规格和验收条件。
- 原始数据表、公式、数据字典、数据转换脚本/版本及导入后的模型表。
- 原生模型包、对象/表/过程/状态/表达式定义、模型版本及变更记录。
- 运行配置、日志、逐重复结果、结果导出文件和报告中的图表数据。
- 保存、重载和复跑记录（当声明涉及持久化或复现时）。

重要事实尽可能通过独立来源交叉核验。例如将原始工作簿、规范化 CSV、模型内表和文档预期对照。两个来源若共享同一上游转换，不应误称为独立证据；记录它们的来源依赖。

## 3. 独立复算数据和统计

- 从原始行/事件重新计算关键总量、比例、时间、能力边界和约束，不直接采信汇总表。
- 复查主键唯一性、重复/缺失、引用完整性、合法范围、单位、日期覆盖、分类覆盖和转换后的行数/总量。
- 重算均值、方差/标准差、分位数、置信区间、配对差值、服务水平或达标概率；确认样本总体、重复层级、删失和终止口径。
- 核对公式是否量纲一致，时间是工作时间还是日历时间、件数还是批量数、利用率分母是什么、周期从何时到何时。
- 对照逐重复原始值、软件汇总、CSV 导出和报告表，检查排序、过滤、四舍五入、缺值和单位转换造成的偏差。
- 统计方法不适用或原始重复数据缺失时，不伪造复算结果；说明可确认的范围和无法验证的部分。

## 4. 算术、守恒和模型边界检查

根据模型的实体、订单和库存机制定义适用的核算式。常见检查包括：

```text
期初在系统数量 + 新进入数量
    = 完工数量 + 报废/取消数量 + 期末在系统数量

期初库存 + 入库/生产
    = 出库/消耗 + 损耗 + 期末库存

每项工作需求量
    = 已完成 + 未完成 + 明确取消/报废的工作量

资源占用不超过资源容量及可用日历；忙时、故障、换型和排班时间口径不重叠
```

检查数值结论的内部自洽性，以及模型统计边界是否与业务问题一致。Little 定律等关系只在其稳态/流量和时间窗口适用条件成立时使用。对不守恒差异追踪事件和边界，不能通过调整显示、隐藏队列或截断统计来消除差异。

## 5. 跨 Issue、场景和版本一致性

- 将多个 Issue 中应保持不变的假设、控制、单位、场景边界和响应定义并列比较。
- 比较场景前确认除目标研究因素外，其余输入、模型机制、统计窗口、预热、终止条件和随机配对设计相同。
- 将每组结果绑定到模型版本/哈希、输入快照/转换版本、实验配置、随机流、重复、开始/完成时间和软件版本。
- 依据时间戳和变更记录判断结果产生时的模型状态；当前文件不能证明旧结果与当前模型一致。
- 对同一对象的不同版本读取实际属性和表达式并做差异比较；关注被引用字段、触发器、路由和响应是否同步变化。
- 对保存结果与发布 CSV/报告值进行逐值或可解释精度比较。版本不同或总体不可比时分开报告。

## 6. 模型实现核查

不只阅读规格和截图；在接口和格式允许时，检查原生模型内部实现：

- 数据表/外部源绑定、主外键、行引用、对象属性和模型表达式是否落实规格。
- 过程、触发器、步骤连接、事件顺序、分支出口和异常路径是否正确配置且实际可达。
- 实体身份、当前位置、责任/资源归属、队列状态、工单关联和统计边界是否清晰，是否有意外混用。
- 随机性是否启用，抽样时点、分布参数、相关结构和随机流是否符合约定；配置标志本身不足以证明运行实际抽样。
- 日历、班次、预热、资源需求、批次、阻塞/放行、故障维修、取消/报废和结束条件是否符合声明。
- 正常、取消、报废和异常退出是否释放资源、清理队列/引用和更新守恒状态。
- 必要时比较原生运行跟踪、对象状态和结果，验证设计的触发点确实执行。

对于非 Simio 平台，使用等价的原生模型结构和运行数据检查，不强行套用 Simio 对象名称。

## 7. 活模型核查和复现

- 活模型审查默认只读，先列出本轮允许的读取接口和禁止的变更接口；不可确认工具是否只读时先检查接口定义。
- 读取前验证当前活动模型和运行状态。记录是否处于设计时、运行中、暂停或实验结果状态。
- 只有核查需要且获得了相应授权时才重跑模型。重跑前确认运行设置，不要覆盖对照所需的输入或历史结果。
- 随机模型复跑应确认发生了真实计算：检查新的运行标识/时间、场景/重复状态、运行日志和计算持续时间。结果相同本身既不能证明复用缓存，也不能证明重新计算。
- 若必须添加临时测试场景或临时变更，记录精确变更，运行后恢复并重新读取确认；不要删除或覆盖用户数据来清理测试现场。
- 保存/重载声明须通过实际保存包、重新加载身份和关键回归检查核实。没有保存重载证据时，不得将其表述为已验收。

## 8. 逐条核查“已修复/已完成”声明

把每条声明拆成可观察的断言，例如“字段已新增”“过程已触发”“运行无错误”“结果已复现”“保存包已重载”。每一条单独检查：

1. 直接读取修复后的文件、模型或原始结果。
2. 对照修复前版本定位实际差异。
3. 运行与该声明对应的最小验证，并按风险决定是否需要回归测试。
4. 检查该变化是否引入新的差异或影响依赖 Issue。
5. 对没有证据的子声明标为无法验证，不因同一报告中的其他项目通过而推定通过。

## 9. 发现和结论格式

每条结论使用以下状态之一：

- **已证实**：指定范围内有直接证据，独立复算/运行检查通过。
- **与事实不符**：一手证据或复算与该声明直接冲突。
- **无法验证**：缺少模型、输入、原始重复数据、运行身份或其他必要证据。

每条发现记录：断言/检查项、状态、证据路径或模型路径、对象/字段/场景、原始值、独立计算、版本/时间、影响、局限。把事实发现和修改建议分开。最终摘要说明本轮核查覆盖范围、未覆盖内容和可支持的结论。
