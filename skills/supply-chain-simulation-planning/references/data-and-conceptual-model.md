# 数据与概念模型

在把文档和运营数据转成模型规格时使用本参考。

## 假设分类

| 类别 | 含义 | 记录方式 |
|---|---|---|
| 来源事实 | 从明确来源直接摘取或测量的内容 | 记录来源、版本、期间及歧义 |
| 确认约束 | 业务责任人确认的规则或边界 | 记录确认人、适用范围和生效日期 |
| 派生估算 | 根据来源字段重新计算的值 | 展示方法、单位和独立核查 |
| 建模假设 | 对未知项的暂定表示或简化 | 说明影响、敏感性和关闭责任人 |
| 实现选择 | 用软件机制表达业务逻辑的选择 | 在目标软件版本中验证行为 |
| 结果 | 指定模型版本和实验运行产生的输出 | 绑定输入、实验、场景、重复和响应定义 |

不能让设计选择悄然变成业务规则。假设变化要关联受影响的模型和结果版本。

## 概念模型最低记录项

对每类流程，至少定义：

- 实体类型、标识、产品/变体、数量和生命周期状态。
- 到达或释放触发、投放控制、路由、优先关系和完工条件。
- 作业时间含义：经过时长、人工内容或按速率折算的工作量。
- 资源需求：人数、技能、共享资格、分配策略、工作日历，以及人员随实体移动还是留在原工位。
- 队列/缓冲位置和容量、优先规则、阻塞、饥饿、溢出及线外工作。
- 每个时间间隔的口径：日历时间、排班时间、有效生产时间或工作日约定。
- 异常路径：报废、取消、故障、返工、缺料，以及仿真结束时未完工的订单。
- 输出指标及其采集/累计事件。

如果业务概念将实体当前位置与未完工作责任分开，两者应显式表达，不能互相推断。

## 数据审查

至少检查：

1. 主键唯一，必需外键均能匹配。
2. 必需字段已填写；没有明确规则时，不把空白转换成零。
3. 不同来源的单位、时间口径和编码一致。
4. 来源、标准化数据和模型导入阶段的数量与总量可对账。
5. 作业时间、能力和资源数量合法且在合理范围内。
6. 每个场景都覆盖所需产品、路线、资源和工作日历。
7. 派生字段可以用来源字段独立重算。

保持原始数据不变，将标准化数据和转换过程作为独立、有版本的数据制品保存。遇到宏或插件公式时，确认它是缓存值、可执行公式还是手工转换参数。公式名称相同不代表目标仿真平台具有相同的抽样语义。

## 指标契约

每个 KPI 都应说明：

| 字段 | 必须定义的内容 |
|---|---|
| 名称 | 业务名称和稳定标识 |
| 总体 | 纳入的实体、需求、资源或事件 |
| 分子/分母 | 比率和百分数的确切数量 |
| 时间边界 | 起止事件、预热期、仿真期和日历口径 |
| 统计量 | 均值、分位数、最大值、时间平均、计数或达标概率 |
| 单位 | 转换前后保持一致并标注显示单位 |
| 终止规则 | 未完工作和期末删失如何处理 |
| 决策用途 | 支持的门槛、比较或取舍 |

总体或观测窗口不同的指标不能直接比较。有限批次系统要区分相邻完工间隔 CT、单件流程时间、批次完工时间和末端清空时间。
