## 输入与时间边界

| 项目 | 确认规则 |
|---|---|
| 研究期间 | 20 个工作日；没有实际年月日，使用相对工作日编号 |
| L 需求 | 每工作日 600 件，20 天合计 12,000 件 |
| R 需求 | 每工作日 320 件，20 天合计 6,400 件 |
| 到期点 | 每工作日结束；有效工作日为 `2 × 27,600 = 55,200 s` |
| 精确时间 | 第 d 天到期为 `d × 55,200 s`；CSV 的整数秒为权威时间，小时列仅便于导入和核对 |
| 终点 | 第 20 天为 `1,104,000 s = 306.666666666… h`，必须计入最后一天需求 |
| 期初需求积压 | 本研究不另加历史客户积压；历史 WIP 不等于历史未交订单 |

Wu 于 2026-11-15 确认非工作时间一律不计入仿真（A-022）。这是有效工时轴，不能当作包含夜班间隔、休息和周末的真实日历。工作日换算为有效小时/(55,200/3,600)；工作时段内的故障/维修、排队和换型仍消耗该时钟。B2 增加工时或以后经批准加入日历时，需求仍为每工作日 600/320；到期时刻由该场景的工作日结束映射，不能原样沿用本表的小时数。

## 分配和发运规则

1. L/R 分别建立需求 FIFO：优先满足较早到期、尚有余量的需求；L 库存不能满足 R 需求。每天到期时登记当天需求，不另设提前发运业务。
2. 允许按件部分交付。同一实体含 20 件时，需求分配按实际件数；尾批按 10 件或实际数量，不强制凑满托盘。需要部分分配时必须保留实体剩余数量或等效库存明细，不能重复消耗整实体。
3. 初始 W05 成品 2,700 L / 1,440 R 是可用成品；其余初始 WIP 必须完成剩余工序后才成为可用库存。本期生产完成 Assembly #2 后同样进入可用成品边界。
4. 到期点先结清同刻完成和入库，再按需求 FIFO 分配发运，最后登记该日准时/未满足量。暂不改变运输时间和 Shipping 无限容量假设。
5. 无需求时剩余成品留存，不自动送入 Sink。发生缺货时，未交需求保留为积压；后续可用成品优先补交旧需求，再服务后来需求。
6. 发运时间不晚于需求到期点的数量计为准时；超过到期点为迟交，即使在期末前补齐，也不能追溯改为准时。一个工件只能分配一次，一个需求余量只能扣减一次。
7. 同时有库存 FIFO 时，以进入可用成品边界的时刻、稳定序号排列；初始成品在 t=0 可用。保留初始 WIP/生产批次标签，用于追溯货源。
8. 期末先处理第 20 天到期点的合法同刻事件，再生成结果；禁止用随意增加运行时长的方法让第 20 天超期发运被记为准时。

原生实现必须验证 Simio 的终止事件优先级及同刻回调顺序，不能通过随机优先级或隐含时间容差决定达标。V0.12已按整数有效秒和晚优先级验证同刻及第20日终点；随机统计复制由09后续研究负责。

## 指标与账本

正式名为 `DueDateUnitFillRate`，显示为“方案 A 按期件数满足率”；现有 `FillRate` 作为项目别名。它不是订单 OTIF，也不预设与作者软件的即时库存 Fill Rate 等价。

对产品 p、每日需求 d：

`Q_due[p,d] = Q_on_time[p,d] + Q_late_by_H[p,d] + Q_unfilled_at_H[p,d]`

`Rate[p] = sum(Q_on_time[p,d]) / sum(Q_due[p,d])`

`Rate[Total] = (OnTime_L + OnTime_R) / 18,400`

总率按件数加权，不能将 L/R 两个百分比简单平均。到期需求非负，分配数量不得超过剩余需求或可用库存；0 分母返回 N/A。生产释放量、全部完工量或全部 Shipping 量都不是分母。

需求账本最小字段：`DemandID`、产品、工作日、精确到期秒、到期数量、准时量、截至 H 的迟交量、期末未交量。发运分配账本至少有：`DemandID`、货源 cohort/批次、实体或库存标识、件数、实际发运时刻、准时标记。L/R 分别报告到期需求、准时、迟交、期末积压及期末可用成品。

对已到期的需求，期末未满足是已知未达标，不是右删失样本；不能从分母删除。CT 的期末未完成样本另按 [07.md](07.md) 管理。初始 WIP 未知历史 Stamping 进入时刻，不能混入新生产的完整 ManufacturingCT。

供应侧必须保留独立守恒：初始工件 + 本期释放 = 实际发运 + 期末工件 + 合法报废。发运量 = 准时分配 + 迟交分配；未分配成品仍属于期末工件。加入 W05 和需求控制后，V0.11 的 `19,630` 件发运、`15,900` 件期末 WIP 不再是新版本必须复现的目标，历史证据不改写。
