# V0.19 参数化装配组织实验候选

本次目的：在保留两道装配工序及现有连接的基础上，用属性比较原始分工、改变投产批量、两人各自连续完成两道装配的场景。本文是本次候选版本的实现及验证记录，不替代项目宪章，也不将单次演示作为作者改进效果的校准结论。

状态：活动模型已修改；4个完整随机实验、最小机制运行和长期逐实体证据检查均已完成；用户保存、关闭重开后的验证待完成。

## 1. 用户可控制的场景

模型输入属性在 **VSM 实验控制** 分类中。参数在每次运行前设定，运行中不改变。

| 属性 | 业务含义 | 本候选的范围 |
|---|---|---|
| `VSM_AssemblyMode` | 装配组织方式 | `0`：原始专职分工，每道装配各一人、各一工位；`1`：同一人连续完成两道装配 |
| `VSM_AssemblyParallelWorkers` | 连续装配模式的总人数 | 当前配置 `1` 或 `2`；模式0不启用共享工人，仍为原始两名专职人员 |
| `VSM_LeftProcessBatch` | 每轮左支架投产量，件 | 默认600；20件/实体时可选300的正整数倍，例如300、600、900、6000 |
| `VSM_RightProcessBatch` | 每轮右支架投产量，件 | 派生为 `VSM_LeftProcessBatch*8/15`；不能独立改变比例 |

原始工艺大批量为6000/3200件，小批量示例为600/320件。保持普通聚合实体20件，初始WIP的10件尾盘保持原数量。

改批量时模型同时调整释放间隔：

`每轮间隔秒数 = 552000 × (Left批量+Right批量) / 9200`

因此，6000/3200每10个工作日释放一轮，600/320每工作日释放一轮，300/160每半个工作日释放一轮。长期平均投产量仍为Left600、Right320件/工作日。每轮先释放Left再释放Right；这仍是现行释放机制，不额外引入新的排产策略。

仿真时长固定3680有效工时，即240个工作日，每工作日15⅓小时。`Maximum Arrivals=Infinity`，由仿真结束控制投产截止。非工作时间不计入仿真。

## 3. Facility、资源和Process

生产路线保持 `Weld2 → Assembly1 → Assembly2 → FG`。新增两个逻辑人员资源 `Resource_AssemblyWorker1`、`Resource_AssemblyWorker2`；不模拟人员行走。

模式0：Assembly1、Assembly2容量各为1，新增共享人员资源容量为0；沿用原始专职分工。

模式1：两道Server的并行位置数均为配置人数，但二者共享同一组人员资源。实体只能占用一名工人，工人从装配开始前一直持有至装配二完成，期间不再接其他盘。两个Server容量相加不能作为总人数：默认仍然只有两人。

新增 `VSM_分配连续装配工人`：从启用的工人列表原子占用一人，成功后冻结实体的WorkerID及占用时刻，写入日志，并触发就绪事件。已经持有工人的实体进入装配二时不重新分配。

两道装配的进入附加过程以 `NoWait` 发起派工。`VSM_AssemblyWorkerReady` 约束使实体只有获得工人后才能占用Server容量。这样等待人员不会阻塞入口转移，也不会提前占用工位；工人分配完成事件用于唤醒准入检查。

新增 `VSM_释放连续装配工人`：装配二完成后先记录释放，再仅释放本实体持有的装配人员资源，最后清除Held标志。WorkerID保留供追溯；工位资源仍由标准Server流程管理。

初始WIP位于装配一前时执行两道装配；位于装配二前时只执行剩余的第二道。初始表没有历史人员归属，因此为其分配当前可用工人，不虚构历史WorkerID。

加工时间和既有随机流保留。每个20件聚合实体在两道装配分别累计20次单件时间样本，一名工人持有整盘完成两道工序；没有增加盘内逐件转移，也没有把两台设备视为四名工人。

`VSM_OperationTable.ResourceCount` 保留原始数值输入；新增 `ScenarioPositions` 保存场景派生位置数，装配Server引用该字段。

## 4. 追溯和输入约束

新增 `VSM_Out_AssemblyWorkerLog` 记录Seized/Released、EntityID、WorkerID、来源、产品、件数及事件时刻。`VSM_Out_OperationLog` 的两道装配记录补充EntityID、WorkerID和AssemblyMode，可关联核对同一人连续加工、同一人不存在重叠持有。非装配行不填新身份字段，默认0。

`VSM_Out_RunSummary` 冻结本次模式、人数、左右批量、实体代表件数及期末工人占用人数，避免只凭版本号辨认场景。运行结束时尚在加工的实体可以仍持有人力，应按删失处理，不能直接判定资源泄漏。

`VSM_校验实验输入` 在初始化WIP创建前校验：模式合法、启用人数为1或2、数量大于0、15:8比例、左右批量均能被普通实体件数整除，以及释放轮数不超过预建480轮台账。非法输入终止运行并给出中文提示。派生Right属性隐藏且保留校验，防止实验中被独立改写。

需要超过两名连续装配工人时，应先扩展资源列表、WorkerID映射、人数校验和日志检查，再开放相应属性值；当前不能仅将人数填成3或更大。

## 5. 验证与证据

最小确定性案例：4盘、每盘20件，初始都在装配一前，无新投产。两道单件时间分别62秒和40秒。

| 场景 | 80件全部完成装配的理论时刻 | 原生结果 |
|---|---:|---:|
| 原始专职分工 | 1.600000小时 | 1.600000小时 |
| 一人连续两道装配 | 2.266667小时 | 2.266667小时 |
| 两人并行、各自连续两道 | 1.133333小时 | 1.133333小时 |

混合初始WIP案例：装配一前90件（含10件尾盘），装配二前80件；170件全部完成，资源正常释放、件数差额0。同WorkerID跨两道装配、持有区间不重叠等检查已通过。

开发中曾发现“等待人员的进入附加过程阻塞转移”导致混合初始WIP互锁；该实现已由异步派工及人员就绪约束替代。保留失败证据供追溯，最终验证以 `final-mechanism-*.json` 为准。
