# VSM 基线解析检查

这些检查在仿真运行前执行，用于发现单位、转录和边界错误。它们不是仿真结果。

## 需求与节拍

- 月需求：`12,000 + 6,400 = 18,400 件/月`。
- 平均日需求：`18,400 / 20 = 920 件/工作日`。
- 有效月时间：`20 × 15.3333 h × 60 ≈ 18,400 min`。
- 节拍：`18,400 min / 18,400 件 = 1 min/件 = 60 s/件`。
- 转移托盘数：`18,400 / 20 = 920 托盘/月`，假设月需求可被托盘整除。

## 价值增加时间

工序过程时间总和：`1 + 39 + 46 + 62 + 40 = 188 s = 3.1333 min`，与案例给出的 3.13 分钟一致。该值不包含换型、等待、故障或库存时间。

## WIP 对账

- 工序 WIP：`7,000 + 1,700 + 2,450 + 1,840 = 12,990 件`。
- 工序 WIP 天数：`12,990 / 920 = 14.1196 日 ≈ 14.1 日`。
- 成品 WIP：`2,700 + 1,440 = 4,140 件`。
- 成品天数：`4,140 / 920 = 4.5 日`。
- 原料 + 工序 WIP + 成品：`5 + 14.1 + 4.5 = 23.6 日`。

## 能力边界

Assembly #1 的过程时间为 62 秒，而节拍为 60 秒：

`62 / 60 = 1.0333 = 103.33%`

因此在单操作员、没有额外有效时间、没有并行能力的直接解释下，当前需求不可持续。模型应在 B1 中显示能力不足，而不是通过自动截断、隐藏队列或提高资源数让结果“通过”。

## 批量和换型核查

- 按“每两周生产半个月需求”的作者口径，L=`12,000 / 2 = 6,000`、R=`6,400 / 2 = 3,200`。

模型输入采用作者明确给出的 6,000/3,200，并将其标为来源推导。若项目采用不同的月度工作日或批次周期，需重新计算并记录新口径，不能沿用本案例推导值。
