# 从 Michigan Steel VSM 提取的通用仿真基线方法

本文件把案例中的可迁移做法与案例数值分开，作为 `supply-chain-simulation-planning` Skill 的验证样本。案例数字只用于说明方法，不是其他项目的默认值。

## 通用流程

1. **定义决策和基线边界**：写清当前要解释的决策、实体完工边界、运营制度、排除项和错误建议的后果。
2. **登记证据来源**：把图表、表格、历史数据、专家约束和作者模型输出分开登记，记录页码、版本、期间和冲突。
3. **建立事实分层**：将输入分成来源事实、业务确认约束、派生估算、建模假设、实现选择和仿真结果。
4. **建立概念模型**：定义实体生命周期、工艺顺序、批量、资源、日历、队列/缓冲、控制策略、故障/返工和异常出口。
5. **做解析对账**：独立核对需求、节拍、过程时间下限、工作负荷、能力边界、库存天数和守恒关系。
6. **冻结数据和假设**：保留原始数据，另存标准化快照；任何未知值都记录影响、责任人、关闭方式和敏感性方法。
7. **设计最小验证阶梯**：先做静态结构和确定性小例，再测资源竞争、日历边界、批量、故障、初始 WIP、异常退出和完整基线。
8. **设置阶段门**：只有范围、概念模型、数据、指标和验证证据达到要求才从 HOLD 进入 GO；未知项改变模型行为时必须停在 HOLD。
9. **按单因素或明确设计执行实验**：固定输入快照、随机流、预热、时域、复制和主要比较，避免把不同机制的结果混在一起。
10. **交接和沉淀**：交付模型身份、输入、假设、场景、逐重复结果、独立核算、局限和下一步；将通用方法与案例参数分离。

## 每个项目必须产生的最小产物

| 阶段 | 最小产物 | 通过条件 |
|---|---|---|
| 决策定义 | 项目基线 | 决策、范围、目标和验收责任清楚 |
| 来源提取 | 来源登记与事实表 | 关键数字可以回到原始来源 |
| 概念设计 | 模型契约 | 实体、路由、资源、日历、队列和异常边界明确 |
| 数据准备 | 原始/标准化快照与假设登记 | 单位、主键、总量和缺失项可对账 |
| 解析检查 | 独立核算 | 节拍、能力、WIP、过程时间和守恒关系通过 |
| 验证设计 | 测试矩阵 | 每个测试有预期、容差、证据位置和失败处理 |
| 阶段审查 | GO/HOLD/REWORK/STOP 记录 | 判定依据与未决事项一致 |
| 实验准备 | 实验矩阵 | 变化因素、固定控制、响应和统计设计明确 |
| 交接 | 证据包 | 模型/输入/结果/版本可复现，限制明确 |

## 可迁移的审查规则

- 图上的库存天数不能直接等同于模型中的实体数量；必须说明计量单位和转换规则。
- 生产批量、转移批量、订单批量和库存快照单位必须分别命名，不能因为数值相同而合并。
- 只有目标可用率时，不应伪造唯一的 MTTF/MTTR；可以选择实现机制，但要保留来源值和敏感性计划。
- SCV 只说明变异程度，不自动指定 Gamma、Lognormal 或其他分布；分布族是实现选择。
- 价值增加时间、制造周期、客户总周期、批次完工时间和库存天数必须分别定义。
- 作者报告的模型结果只能作为条件性对照，必须绑定可比的输入、随机性、统计窗口和终止规则。
- “模型可以加载”或“运行无错误”只是实现检查，不能替代概念有效性和运营确认。
- 初始库存若无法恢复历史批次结构，应明确从哪个事件开始执行批量守恒，并为初始快照设置独立口径。

## 本案例对 Skill 的验证意义

Michigan Steel 案例能够检验 Skill 是否会：

- 先做来源和单位核算，再进入平台建模；
- 识别 62 秒工序相对于 60 秒节拍的能力边界；
- 把作者假设和现场事实分开；
- 在关键输入不完整时保持 HOLD；
- 不把作者的校准结果写成自己的仿真结果；
- 把后续批量、平衡、维修和加班作为实验，而不是偷偷写进当前状态。

它不能单独证明该流程适用于所有供应链项目。通用 Skill 仍需用至少一个不同结构的案例（例如多路线、共享资源、返工或物流运输）继续验证。
