# Michigan Steel VSM 项目路线

## 项目定义

- 项目：Factory Physics for Managers 第 9 章 Michigan Steel VSM 案例。
- 目的：按作者示例逐步建立并验证 Simio 模型；先完成用户指定的 VSM 基线，再按阶段比较作者提出的方案。
- 基线要求：本案例需要基线供后续方案比较。基线定义属于本案例要求，不是 Skill 对所有项目的通用要求。
- 当前活动模型：Simio 活动会话 `/Project/Model`；MCP 读取的模型属性版本为 `VSM_V0.7_InitialWIPTable`，阶段标识为 20 件计算批次实现增量。V0.7 已保存、关闭、重新打开并完成原生回归；详见 [V0.7 证据](vsm-v07-20piece-entity-evidence.md) 和 [交接清单](release-manifest-v0.7.md)。
- I1 起始模型：以 V0.6 逐件实体模型为参照，V0.7 是降低实体数量的计算批次候选状态。模型文件身份、诊断、运行警告、件数守恒和实体数守恒已在重载后复核；详细队列/批内时序等价性仍未验证。
- 当前轮次：`I1`，阶段门 `HOLD`。I1 文档和 V0.7 交接记录已建立，但正式 VSM 基线 `B0/B1` 尚未完成。

## 基线在路线中的位置

本项目的基线由 `I1.6` 定义和确认：先将 Figure 9-1 当前状态作为 `B0`；在明确作者假设后建立初始仿真 `B1`；如需对照作者校准输出，再单独建立 `B2`。现有结构原型不是 B0/B1/B2。基线输入、状态和用途见 [01-project-baseline.md](01-project-baseline.md)，证据边界见 [I1/09](iterations/I1/09.md)。

## 依赖与 I1 阶段门

```text
I1.1 → I1.2 → I1.3 → I1.4 → I1.5 → I1.6 → I1.7
```

**当前判定：HOLD。** V0.7 的保存/重载回归已完成；解除 HOLD、进入正式 B0/B1 前仍需完成：

1. 保留 V0.7 作为已重载的计算批次候选，并在后续维护中统一旧实验/对象元数据；V0.4 的重载缺口不再作为当前版本阻塞项。
2. 若研究问题要求物理托盘，需明确 20 件计算实体与物理托盘的关系、批内完成语义和尾批守恒；V0.7 已证明加权总量守恒，但尚未证明逐件动态等价。
3. 按已接受口径实现 27,600 秒/班、过程批量作用点和释放规则；若不表达班间停顿，记录为模型限制。
4. 将来源目标可用率与实现用 MTTF/MTTR、分布族等值分列，冻结将用于下一次可复现运行的输入版本。
5. 按 `05-verification-plan.md` 逐项记录预期、容差、实际结果、证据和结论状态；把 V0.7 已通过的计算批次子集、未测的物理/动态测试和 V0.6 等价性测试分开。

之后按 I1.4–I1.6 完成 B0/B1 建模和验证。B2 只作为单独校准状态；不得用校准结果覆盖 B0/B1。I2 才进入作者方案或用户选定的实验增量，实验主题和轮数由 I1.7 评审后确定。
